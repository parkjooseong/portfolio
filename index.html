개발 배경

계약 내용을 충분히 이해하지 못한 채 불리한 조건을 받아들이는 소상공인의 문제에 주목했습니다. 부산 관광상권 소상공인이 광고대행 계약을 확인하고 조정을 준비할 수 있도록, 팀이 AI 계약 관리 서비스를 만들었습니다.

담당 업무

문서 업로드·분석 결과 조회·역제안 비교 등 백엔드 기능을 구현하고, 데이터베이스와 외부 AI API를 연결했습니다.

개발 노트 AI 비교 실패에 대비하고, 조정 기능과 연결하기

AI 비교가 실패해도 상대방의 응답은 남도록

계약 상대방의 수정 제안인 역제안을 AI로 비교하는 기능을 맡았습니다. 외부 AI가 응답하지 않거나 잘못된 결과를 반환해도, 상대방이 이미 제출한 제안과 사유는 보존해야 했습니다.

저는 응답 저장과 AI 비교를 분리하고, 저장된 요청 문구·역제안·사유를 비교 서비스가 읽도록 구현했습니다. 비교 결과의 항목 ID도 요청과 대조해, 결과가 누락되거나 다른 항목의 설명이 섞이면 오류로 처리합니다.

AI 호출을 의도적으로 실패시키는 테스트를 추가했습니다. 비교 조회는 오류를 반환하더라도 먼저 저장한 역제안 문구와 사유가 그대로 남는지 확인하도록 했습니다.

팀 협업 · 저장과 비교의 연결 기준 맞추기

조정 요청·응답 기능과 AI 비교 기능은 담당이 나뉘어 있어, 서로 넘기는 데이터와 오류 처리 범위가 맞아야 했습니다. 저는 기존 조정 상세 조회에 비교 서비스를 연결하고, 공통 항목 ID로 요청·응답·비교 결과를 연결했습니다.

같은 PR에서 응답 스키마와 공유 API 명세, 연동 테스트도 함께 수정했습니다. 이를 통해 팀의 조정 흐름에 비교 기능을 붙이면서, 비교 단계의 오류가 이미 완료된 응답 저장까지 되돌리지 않도록 역할을 나눴습니다.

개발 배경

사람들에게 잘 알려지지 않은 책 중에도 지금의 관심사와 연결되는 책이 많습니다. 대출이 적다는 이유로 놓치고 있던 책을 다시 발견할 수 있도록, 팀은 도서관 데이터와 트렌드를 연결하는 추천 서비스를 만들었습니다.

담당 업무

회원 인증과 개인 책장 API를 구현했습니다. 팀의 추천 기능에서는 도서관 조건에 맞춰 최종 후보를 고르는 로직을 보완했습니다.

개발 노트 도서관 조건을 반영해 추천 결과 보완하기

추천 도서가 빠지면 다음 후보로 채우기

트렌드 추천에서 먼저 상위 도서를 뽑고 나중에 도서관 이용 가능 여부를 검사하면, 조건을 통과하지 못한 책만큼 최종 결과가 줄어드는 문제가 있었습니다. 뒤에 적합한 후보가 있어도 결과에 포함되지 않았습니다.

저는 후보를 여유 있게 받은 뒤, 중복 여부와 대상 도서관 조건을 통과한 책만 최종 권수에 포함하도록 선별 순서를 바꿨습니다. 한 트렌드의 후보가 모두 탈락하면 다음 순위 트렌드로 넘어가, 남아 있는 유효한 후보로 결과를 채우도록 했습니다.

상위 두 권은 이용할 수 없고 차순위 두 권은 가능한 상황을 회귀 테스트로 추가했습니다. 이때 차순위 두 권이 최종 목록에 들어가고, 표시 순서가 1·2로 다시 매겨지는지 확인하도록 했습니다.

팀 협업 · 백엔드 기능을 사용자 화면으로 연결하기

팀에서 추천 로직, 회원·책장 API, 화면을 나눠 개발했기 때문에 로그인 정보와 요청·응답 형식이 서로 맞아야 했습니다. 저는 회원가입·로그인·책장 조회·도서 저장과 상태 변경을 기능별 PR로 나눠 구현했습니다.

팀의 API 명세를 기준으로 연동했고, 프런트엔드 담당자는 해당 API를 로그인 상태와 책장 조회·읽기 상태 변경 화면에 연결했습니다. 이후 추천 결과 보완에서는 기존 후보 생성 기능과 도서관 조회 기능 사이의 선별 과정을 수정해, 팀이 연결한 흐름 안에서 문제를 해결했습니다.
